# IMU Reader Lib 代码实现分析

## 整体架构

库采用分层设计，由底向上分为 4 个模块：

```
┌─────────────────────────────────┐
│          IMUReader              │  ← 高层 API：打开设备、配置传感器、读取循环
├─────────────────────────────────┤
│   IMUParser       SerialPort    │  ← 中间层：协议解析 + 串口通信
├─────────────────────────────────┤
│         CRC16                   │  ← 底层：校验算法
└─────────────────────────────────┘
```

### 数据流向

```
SerialPort::read()  ──►  IMUParser::feed()  ──►  callback(IMUData)
     原始字节               逐字节状态机解析           完整帧回调
```

## 模块详解

### 1. CRC16 ([crc16.h](src/crc16.h) / [crc16.cpp](src/crc16.cpp))

**功能**：提供两种 CRC-16 校验算法，用于帧完整性验证。

**实现要点**：

- **查找表加速**：预计算 256 项的 16 位查找表，多项式为 `0x1021`（CRC-16/CCITT），初始值 `0xFFFF`。表中每项代表 8 次移位异或的合并结果，使单字节处理从逐位循环降为 O(1) 查表。

- **两种算法**：
  - `crc16_compute()`：标准 XMODEM 变体，每字节后 CRC 左移 8 位（`crc << 8`）
  - `crc16_v1()`：兼容某些手册描述的变体，CRC 左移 1 位（`crc << 1`）

```cpp
// 核心查表公式
uint8_t index = (crc >> 8) ^ ptr[i];   // 高字节与输入异或作为索引
crc = ((crc << 8) ^ CRC16_table[index]); // 左移后与查表值异或
```

### 2. SerialPort ([serial_port.h](src/serial_port.h) / [serial_port.cpp](src/serial_port.cpp))

**功能**：Linux 串口 RAII 封装，基于 termios API。

**设计特点**：

| 特性 | 实现 | 说明 |
|------|------|------|
| RAII 生命周期 | 析构函数自动 `close()` | 防止 fd 泄漏 |
| 不可拷贝 | `= delete` 拷贝构造/赋值 | 防止 fd 被多次 close |
| 配置模式 | 8N1 原始模式 | 8 数据位，无校验，1 停止位 |
| 读取模式 | VMIN=0, VTIME=1 | 非阻塞，超时 100ms |
| 流控 | 全部关闭 | 无硬件流控(CRTSCTS)、无软件流控(IXON/IXOFF) |

**open() 流程**：

1. 先 `close()` 已打开的 fd（允许重新 open 到不同设备）
2. `::open(device, O_RDWR | O_NOCTTY)` 打开设备，`O_NOCTTY` 防止成为控制终端
3. `tcgetattr()` 获取当前配置
4. 设置波特率（通过 `baudToConstant()` 将整数映射为 `Bxxx` 常量，支持 9600 ~ 4000000）
5. 配置控制标志：`CS8 | CREAD | CLOCAL`，清除 `PARENB | CSTOPB | CRTSCTS`
6. 配置本地标志：清除 `ICANON | ECHO | ECHOE | ISIG`（原始模式）
7. 配置输入输出标志：清除所有转换处理和流控
8. `tcsetattr(fd, TCSANOW, ...)` 立即应用

**非阻塞读取策略**：`VMIN=0, VTIME=1` 表示只要有数据就立即返回，无数据时最多等待 1 个 decisecond（100ms）。适合上层轮询循环，不会永久阻塞。

### 3. IMUParser ([imu_parser.h](src/imu_parser.h) / [imu_parser.cpp](src/imu_parser.cpp))

**功能**：解析 IMU 二进制帧协议，通过有限状态机逐字节提取完整数据帧。

**协议帧格式**：

```
┌──────┬──────┬──────┬──────┬──────────┬───────────┬──────┐
│ 0x55 │ 0xAA │  ID  │ TYPE │  DATA    │  CRC16(LE)│ 0x0A │
│ SYNC1│ SYNC2│ 1B   │  1B  │ 12/16 B  │    2B     │  1B  │
└──────┴──────┴──────┴──────┴──────────┴───────────┴──────┘
```

**帧类型与数据长度**：

| TYPE | 含义 | 数据长度 | 数据格式 |
|------|------|----------|----------|
| 0x01 | 加速度 | 12 字节 | 3 个 float32 (x, y, z)，单位 g |
| 0x02 | 角速度 | 12 字节 | 3 个 float32 (x, y, z)，单位 °/s |
| 0x03 | 欧拉角 | 12 字节 | 3 个 float32 (Roll, Pitch, Yaw)，单位 ° |
| 0x04 | 四元数 | 16 字节 | 4 个 float32 (W, X, Y, Z) |

**状态机设计**（8 个状态）：

```
SYNC1 ──0x55──► SYNC2 ──0xAA──► ID ──► TYPE ──► DATA ──► CRC1 ──► CRC2 ──► END_MARKER
  │               │                        │                              │         │
  └── 非0x55 ─────┘                        └── 未知type ──► SYNC1        │         │
                                                                          │         │
                                                             0x0A: processFrame()
                                                             非0x0A: 丢弃
```

- 连续读取中如果下一个字节是 `0x55`，则保持 `SYNC2` 状态（处理 `55 55 AA` 场景）
- 未知帧类型直接回到 `SYNC1`，不需要结束符回溯
- 每个 `END_MARKER` 后无条件返回 `SYNC1`，保证状态机始终前进

**CRC 校验的容错设计**（`processFrame()` 核心逻辑）：

考虑到手册可能存在的歧义，共尝试 4 种 CRC 计算范围 × 2 种多项式算法 × 2 种字节序 = 最多 16 种组合：

- **4 种范围**：
  - `scope1`：ID + TYPE + DATA
  - `scope2`：TYPE + DATA
  - `scope3`：仅 DATA
  - `scope4`：55 AA + ID + TYPE + DATA

- **字节序回退**：若原始 CRC 不匹配，交换高低字节再尝试

```cpp
// 首次匹配：received_crc 原始字节序
crc16_compute(scope, len) == received_crc || crc16_v1(scope, len) == received_crc

// 二次匹配：received_crc 字节交换后
crc16_compute(scope, len) == swapped || crc16_v1(scope, len) == swapped
```

**数据累积与回调触发**：

`IMUData.updated` 字段是位掩码（bit 0=accel, bit 1=gyro, bit 2=euler, bit 3=quat），每次成功解析一帧后对应位置位。**回调在所有帧类型到达时都触发**，因此上层会收到 4 次同设备的数据回调，逐渐填满 `updated` 字段——但每次回调后会清零 `updated`（第 184 行），这意味着回调只携带当前帧的类型数据。

### 4. IMUReader ([imu_reader.h](src/imu_reader.h) / [imu_reader.cpp](src/imu_reader.cpp))

**功能**：高层 API，组合 `SerialPort` 和 `IMUParser`，提供开箱即用的 IMU 读取能力。

**核心 API 含义**：

- `open(device, baud_rate)` — 打开串口，默认波特率 921600
- `configure()` — 发送一系列配置命令，依次启用加速度、角速度、欧拉角、四元数输出，设置 USB 输出通道，保存参数到 Flash，返回正常模式
- `setCallback(cb)` — 注册数据回调
- `update()` — 读取串口数据并喂给解析器（非阻塞），返回读取字节数
- `sendCommand(cmd, len)` — 发送原始命令

**configure() 配置序列**：

```
进入设置模式(100ms等待)
   ├── 启用加速度输出(20ms)
   ├── 启用角速度输出(20ms)
   ├── 启用欧拉角输出(20ms)
   ├── 启用四元数输出(20ms)
   ├── 设置USB输出(20ms)
   ├── 保存参数到Flash(100ms)
   └── 返回正常模式(100ms)
```

每条命令格式为 `0xAA <CMD> <PARAM> 0x0D`，命令间需等待传感器处理。

## 设计模式与工程实践

### RAII 资源管理
`SerialPort` 在析构函数中自动关闭 fd，避免资源泄漏。`IMUReader` 通过组合持有 `SerialPort`，无需手动管理。

### 不可拷贝语义
`SerialPort` 和 `IMUReader` 都禁止拷贝（持有 fd 和回调资源），通过 `= delete` 明确表达。

### 回调模式
解析器和读取器都使用 `std::function<void(const IMUData&)>` 作为回调，松耦合数据消费逻辑。

### 编译配置
- C++17 标准
- 静态库 `libimu_reader_lib.a` + 示例可执行文件 `imu_reader_example`
- 编译警告全开：`-Wall -Wextra -Wpedantic`

## 关键限制与注意事项

1. **仅支持 Linux**：`SerialPort` 依赖 termios、`<fcntl.h>`、`<unistd.h>`
2. **非线程安全**：`IMUParser` 的状态机有内部状态，多线程调用 `feed()` 会竞争
3. **回调触发语义**：每次 `update()` 可能触发多次回调（每帧一次），回调中避免耗时操作
4. **CRC 回退开销**：不匹配时最多计算 16 组 CRC，但只在帧边界发生，实际性能影响极小
5. **数据更新不累积**：`IMUData.updated` 在每次回调后被清零，不会跨帧累积
